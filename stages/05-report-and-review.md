# Stage 5：报告与双向一致性审阅

## 任务

只从通过审计的 Claim ledger 写报告，使读者既能先看答案，也能回到原音和边界。

## 动作

1. 先写摘要式答案：一句短回答、3–5 条单句结论、1–3 条单句建议和一行整体边界。摘要不放长原音、source_id 列表、完整推理链或数据账目；这些内容下沉到正文证据卡。
2. 再补数据来源、方法分析、支持/反证、来源索引和限制，不按执行时间写流水账。
3. `report.md` 与 `report.html` 共用同一组 claim、数字和 `source_id`；HTML 不得发明新结论。
4. 将已审阅内容写入最小 `report-data.json`，运行 `node scripts/render_report.mjs report-data.json report.html`，统一使用共享 shell 和主方法专属模块。不得为项目临时编写另一个 HTML 生成器；如现有 renderer 真正无法表达方法主图，修正 Skill 的共享 asset 而非继续分叉。
5. 从报告反向抽查：报告句 → claim_id → evidence/counter IDs → locator → 原始语境。然后只运行一次 `node scripts/validate_run.mjs RUN_DIRECTORY`；失败时修正原产物并重跑同一命令，不改写或绕过 Validator。
6. 验证通过后，优先运行 `node scripts/review_report.mjs report.html OUTPUT_DIRECTORY`，在同一浏览器会话中一次生成 1440px 桌面首屏、390px 首屏、打印 PDF 与 DOM 审计结果。需要启动本地浏览器且环境受沙箱限制时，直接申请所需权限，不先运行一个已知会失败的沙箱内浏览器命令。若环境缺少 Playwright，才使用已有浏览器工具完成同一最小批次并在日志注明。默认最多做一次视觉模型目检；只有此次指出具体异常才针对异常复查，不对同一页面反复请求泛化意见。
7. 全部检查通过后，立即用当前环境可用的本地浏览器或 HTML 预览器直接打开 `report.html`；不能只在交付信息中给出路径。

## Gate

- 事实、解释、假设和建议在文字与视觉上可区分。
- 首屏在不阅读证据细节时也能快速复述答案；字号和卡片密度不与正文争夺注意力。
- 1440×900 首屏不滚动即可看到一句核心答案和至少三条短结论；报告大标题不得占据半屏以上。
- 关键引用能回溯，数字有分母，限制贴近受约束的结论。
- Markdown 与 HTML 的结论、数字、来源和置信度一致。
- `report.html` 已直接打开供用户查看。
- `validate_run.mjs` 通过，且视觉模型目检不超过一次（除非首次发现明确异常）。
- `report-review.json` 的机械视觉检查通过；若脚本因环境依赖不可运行，日志中记录等价检查及原因。
- 报告标题、方法说明和主图准确反映实际执行强度；阶段性信号诊断不伪装成完整研究。
