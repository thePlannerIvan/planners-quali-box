# Markdown 与 HTML 报告契约

## 单一内容源

先使用 `report-template.md` 完成 `report.md`，审阅结论、数字和来源后，再组装 `report.html`。两份文件的关键结论、统计分母、source_id、置信度和限制必须一致；HTML 只改善阅读，不创造新分析。

## 统一阅读顺序

1. **先看答案**：一句话回答、3–5 个关键结论、优先建议、整体置信度、决策边界。
2. **数据资料**：每个原始文件的来源、取得方式与日期、时间范围、原始/有效记录、字段、清洗、证据角色和缺口。
3. **方法分析**：方法专属主图与推理过程。
4. **证据审阅**：原音、反证、置信度和行动验证。
5. **附录**：参数、详细来源索引、限制与下一步。

不要按“我先运行了什么脚本、然后做了什么”的时间顺序写正文；执行日志放 `run-notes.md`。

## 数据资料硬规则

- 一个原始文件一行，不能只写“来自小红书数据”。
- 记录文件名/工作表、平台或机构、采集方式、取得日期、数据时间范围、原始记录数、有效记录数和在分析中的角色。
- 无法确认的信息写“未知—待补充”，不根据文件名或语气猜测。
- 每个统计数字附分母、过滤条件和生成方式；重要数字应能由保存的查询、脚本或明确规则复算。
- 解释原始条数 → 去重 → 排除 → 有效样本的账目关系；不同口径不得在同一段混用。
- 来源索引至少包含 `source_id`、数据集 ID、原始行/工作表/URL/note_id、原文或摘要及证据角色。

## HTML 合成

1. 复制 `report-shell.html`。
2. 把对应 `methods/*.html` 整体放入 `<!-- METHOD_MODULE -->`。
3. 用 `report.md` 的已审阅内容替换全部 `{{...}}`。
4. 不加载 CDN、远程字体或外部 JS；必要图形使用内联 SVG。
5. 不删除导航、水印、数据资料、来源与限制模块。

## 共享但不统一视觉

所有方法共享：结论优先区、数据资料、证据编号、反证、置信度、来源索引、可隐藏导航、打印样式和“阿祖不看 TVC · demyth.info”水印。方法模块决定色彩、构图、主图和分析节奏。

### 结论卡要求

关键结论不是方法标签，必须直接回答业务问题。首屏的每条结论至少能指向正文中的证据卡；建议说明动作、对象、理由和验证方式。

### 证据卡

```html
<article class="finding">
  <p class="eyebrow">CLAIM</p>
  <h3>可反驳的一句话结论</h3>
  <p class="reasoning">解释链</p>
  <ul class="evidence"><li><code>S-001</code> 原音</li></ul>
  <div class="counter"><b>反证 / 边界</b> ...</div>
  <span class="confidence confidence--mid">中置信</span>
</article>
```

置信度只能是高/中/低，并解释依据。每条引用必须能在来源索引定位。

## 导航与水印

- 每个主章节使用唯一 `id` 与 `data-nav-title`；页面脚本自动生成导航。
- 桌面导航默认展开，移动端默认收起；按钮必须同步 `aria-expanded`，遮罩可关闭导航。
- 导航状态可记忆，但 `localStorage` 不可用时也能正常工作。
- 作者水印固定为“阿祖不看 TVC · demyth.info”，屏幕端低干扰、打印端保留；不得放入可能被方法模板替换的占位符。

## 视觉验收

- 1440px 与 390px 均无横向溢出；导航展开和收起各检查一次。
- 首屏无需滚动即可理解报告回答了什么、置信度多高。
- 正文不小于 15px，图注不小于 12px；不只用颜色表达含义。
- SVG 标签不互相遮挡；NeedScope 的点过多时用编号和图例，不把所有长标签堆在轮盘中央。
- 打印时水印可见，导航不打印，卡片不被随意拆页。
- 不存在未替换占位符、空证据列表、虚构链接或外部依赖。

## 内容验收

- 结论与建议早于数据和分析过程。
- 数据资料能让后续分析者重新定位原始数据并理解口径。
- 主结论都有 evidence / counter-evidence / confidence。
- 事实、编码、解释和建议可区分；互动量不冒充代表性。
- 方法主图符合对应 Reference，不能互换。
