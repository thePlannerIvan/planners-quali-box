# QualiBox System Map

## 目的、用户与尺度

QualiBox 帮助研究、策略与品牌团队从社媒内容、开放题和访谈中选择合适的定性方法，形成可回到原始语境的判断。系统采用 **Standard** 三层架构：项目证据链明确、方法按问题检索、Pipeline 可恢复；不建立统一评分、全量方法 Wiki 或复杂 Dispatcher。

非目标：替代正式抽样调查、专有常模、完整民族志、临床/心理测量或财务品牌估值。

## Project Grounding

```text
原始文件与收集情境
→ 原生格式读取与语料账目
→ 研究问题、证据角色与分析单位
→ 用户确认的主方法和辅助镜头
→ 编码、关系链、候选主张
→ Evidence / Counter-evidence 逆向审计
→ report.md / report.html
```

- 原始输入和用户明确决定是项目权威；格式化副本、编码、聚类和解释属于派生知识。
- `source_id` 必须通过规范化语料回到原始逻辑记录及语境；证据节选必须保留可机械定位的连续原文，不用总结冒充引用。
- 当前状态以 `corpus-profile.md` 的研究问题、范围、CP0 确认、阶段和缺口为准，不维护流水日志式 Memory。

## Method System

- **主方法**：一次默认选择一种，负责回答核心研究问题。
- **辅助镜头**：最多两个，只深化已存在的证据，不产生独立总分或替代主方法。
- **研究规范**：在对应数据条件下约束采集语境、伦理和主张边界。
- **来源权威**：原始论文、作者或方法机构的正式资料定义方法；项目经验只能改善执行，不能改写方法身份。

## Work Pipeline

1. Stage 0 建立最低限度 Grounding，推荐一个主方法和至多两个镜头，经 CP0 确认。
2. Stage 1 明确研究设计、证据角色、独立性、数字语境与伦理。
3. Stage 2 对需要全量编码的概念做异质样本校准。
4. Stage 3 只加载被确认的主方法与镜头，形成候选主张。
5. Stage 4 按主张类型逆向审计，并执行方法专属禁区。
6. Stage 5–6 交付双格式报告，区分项目经验、方法修正候选与一次性事件。

## 控制面

- 用户在 CP0 决定研究问题、范围、主方法和辅助镜头；模型负责先完成数据体检并给出推荐。
- 脚本只处理解析、检索、计数、抽样和追溯验证，不判断洞察或框架归类是否成立。
- 多主问题拆成独立分析；不得把多个框架揉成综合评分。
- 每次增加方法都必须说明它独占的问题、证据条件、允许/禁止主张、报告消费者和替代/合并对象。

## 验证与学习

- 工程验证：结构、frontmatter、引用路径、证据管线、HTML 离线与导航。
- 语义验证：路由是否受证据约束、CP0 是否阻止抢跑、方法是否被正确命名、禁区是否有效。
- Baseline：旧版只含五条主路线；新版需在新三类数据上表现为正确路由或诚实降级，而不是都落入 Ogilvy。
- 真实产物仍需用户抽查；结构通过不等于方法效果已经得到长期证明。
