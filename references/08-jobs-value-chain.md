# 消费任务与价值链诊断

## 方法身份

本路线组合两个互补视角：

- **Jobs-to-be-Done（JTBD）**识别人在特定情境下想取得的进展、核心功能任务、相关任务、情感/社会任务和成功结果；
- **Means–End Chain（MEC）**把对象属性或做法连接到使用后果，再连接到个人价值，即 `Attribute → Consequence → Value`。

Laddering 是通过持续追问“为什么这很重要”来引出 MEC 的访谈与分析技术。没有这样的追问轨迹时，只能称为“基于现成文本重建的价值链假设”，不能称为完整 Laddering 研究。Outcome-Driven Innovation（ODI）是带有结果度量和优先级计算的专有流程；QualiBox 不复刻 ODI。

## 适用问题与最低证据

适合回答：消费者在什么情境下需要完成什么、如何判断成功、哪些属性或体验最终服务于什么价值。

优先数据：带“场景—行动—结果—原因”的深访、开放题、日记、长评或用户故事。仅有短句、品牌口号或脱离使用情境的情绪表达时，最多生成待验证的 job/value 假设。

至少区分：

- 情境与触发；
- 核心功能任务；
- 情感或社会任务；
- 期望结果及其判断方式；
- 属性/做法、功能/心理社会后果、个人价值；
- 替代方案、阻碍与不成功经验。

## 工作流

1. 从原文抽取情境、触发、行动对象、期望进展和失败/替代方案，不先套 job 句式。
2. 把“任务”与“解决方案”分开：任务应能在产品或品牌变化后仍成立；品牌、功能和内容形式通常是候选解决方式。
3. 只有原文存在连接时才建立 A→C、C→V；同一文本中的显式链优先，跨文本拼接必须标为聚合假设。
4. 对有追问轨迹的访谈，逐个保留受访者 ladder，再归并概念和直接/间接连接；对现成文本，不制造受访者没有说过的连续 ladder。
5. 比较不同情境、人群和替代方案中的稳定链与断裂链；低频链可保留，但不因表达生动而升级为普遍动机。
6. 输出 job architecture、证据充分的 A-C-V 链、阻碍/替代和下一步验证问题。

## 专属 Gate

- job 描述的是进展或任务，不是产品功能、品牌名或人群画像。
- 每条 A-C-V 连接都能回到同一受访者的追问轨迹，或明确标为跨文本聚合假设。
- `Value` 是较高阶的期望状态或持久目标，不是把普通好处换一个抽象词。
- 没有追问轨迹时，报告名称使用“消费任务与价值链假设诊断”，不写“Laddering 研究”。
- 没有重要性、满意度和结果优先级调查时，不输出 underserved score、机会分数或 ODI 优先级。
- 不把出现频率直接等同于任务重要性，不把品牌传播语当消费者任务证据。

## 输出结构

一句话核心进展 → 情境与任务地图 → 关键 A-C-V 链 → 阻碍和替代 → 证据/反证 → 可验证的产品、体验或沟通假设。
